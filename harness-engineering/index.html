Two-Role Architecture

แก้ปัญหา long-running tasks ที่เกิน context window เดียว:

Initializer Agent

รันครั้งเดียว — session แรกเท่านั้น

  • สร้าง init.sh (dev server)
  • สร้าง claude-progress.txt
  • เขียน feature list (JSON)
  • ทำ initial git commit

Coding Agent

ทุก session ถัดไป — incremental progress

  • อ่าน progress → เลือก feature ถัดไป
  • ทำงาน 1 feature ต่อ session
  • Git commit + update progress
  • State clean สำหรับ merge

Session continuity: Git commits + claude-progress.txt = structured artifacts ที่ทำให้ agent ตัวต่อไปรู้ว่าทำอะไรมาแล้ว

4 Failure Modes และวิธีแก้

One-shotting

พยายาม build ทุกอย่างพร้อมกัน

Fix: Feature list JSON (200+ features ทั้งหมด "failing")

Premature Completion

เห็น progress บางส่วนแล้วประกาศเสร็จ

Fix: บังคับ ทำ 1 feature/session อย่างเดียว

Buggy State

ทิ้งโค้ดไว้ในสภาพพัง

Fix: Git commits + progress file — อ่านทุกครั้งก่อนเริ่ม

Premature Test Passing

Test ผ่านแต่ feature ใช้งานไม่ได้

Fix: Browser automation (Puppeteer MCP) ตรวจ E2E

Key insight: ไม่มี explicit prompting → Claude ทำแล้วแต่ fail จะ recognize ว่า features ไม่ทำงาน E2E

Computational vs Inferential Controls

Computational

  • Tests, Linters, Type checkers
  • Speed: ms–seconds
  • Cost: Low
  • Deterministic ✓

Inferential

  • AI review, Semantic analysis
  • Speed: seconds–minutes
  • Cost: High
  • Non-deterministic ✗

Rule: ใช้ Computational controls ก่อน (coverage, reliability) → Inferential เฉพาะที่ semantic judgment จำเป็น

Source: martinfowler.com — Birgitta Böckeler (ThoughtWorks)

Harnessability — ก่อนจะลงทุน Harness

Properties ที่ทำให้ codebase รับ harness ได้ดี:

Strongly-typed languages → type checker จับ error ได้ computational + ถูก

Clear module boundaries → structural linting ทำได้

Defined service topologies → ย่อ output space ลง

Established frameworks → tooling มีให้ใช้ เลข custom harness น้อยลง

Ashby's Law: Regulator ต้องมี variety เพียงพอที่จะควบคุมระบบ — ถ้าไม่มี topology constraints output space จะใหญ่เกินกว่าจะครอบคลุมด้วย harness ได้

Practical tip: ประเมิน harnessability ก่อน — refactor ให้ boundary + types ดีขึ้น อาจมี leverage สูงกว่าสร้าง harness ซับซ้อนบน codebase ที่สละสลวย

Trae/ByteDance — R.E.S.T.

General Agent Engineering Framework

R.E.S.T. Framework — 4 Core Objectives

R — Reliability

  • Fault Recovery: Auto-resume จาก checkpoints
  • Idempotency: Retry ปลอดภัย ไม่ corrupt state
  • Consistency: Behavior คงเส้นทางเดิม

E — Efficiency

  • Resource Control: Token, API call, compute budgets
  • Low Latency: Quick feedback
  • Throughput: Tasks per unit time

S — Security

  • Least Privilege: Minimum permissions per sub-task
  • Sandboxing: Strict isolation
  • I/O Filtering: Prompt injection defense

T — Traceability

  • E2E Tracing: Full call chain
  • Explainable Decisions: Attribution
  • Auditable State: Query ย้อนได้
